MCP = MODEL CONTEXT PROTOCOL

The open standard for connecting AI to live data.

This module exposes Odoo as an MCP server at POST /mcp. Any MCP client authenticates and can read and write your Odoo — Sales, CRM, Inventory, Accounting, your own custom models — bounded by per-key scopes, permission flags and Odoo’s standard access rules.

★ THE SEMANTIC LAYER

Stop it guessing what your words mean.

A model pointed at a raw Odoo database is doing archaeology. It sees account.move with 180 fields and has to infer that "outstanding" is amount_residual, that a customer invoice is move_type = out_invoice, and that "churned" is a state your company invented. It usually gets there. When it does not, it does not say so — it answers confidently, with the wrong number.

Business metrics
A named, reviewed calculation. The assistant asks for metric_revenue and gets the number your finance team would have produced — not one it improvised from a group-by. Time windows, breakdowns and units included.
Business glossary
Your definition of churn, MRR, overdue, live job — optionally pinned to the model, field and domain that expresses it. Synonyms too, because half your team calls it something else.
Model hints
The single highest-value sentence you can write down: "for revenue use account.move, not sale.order — sale.order includes quotations that never became money." It stops the wrong query before it is made.

None of this grants access. A metric runs as the API key’s user, inside that key’s model whitelist, under that user’s record rules. A glossary entry pointing at a model the key cannot read is simply not shown to it. Everything here narrows and clarifies; nothing here widens.

★ THE GUARD RAIL NOBODY ELSE SHIPS

It asks before it deletes.

Odoo’s access rules stop an assistant doing what the user may not do. They do not stop it doing something the user could do but did not mean to. This does. Deleting, bulk edits and method calls stop until a human has seen exactly what is about to happen.

Bound to the exact call
The approval carries a digest of the arguments it was issued for, so a confirmation for "delete 3 draft quotes" cannot be replayed to authorise "delete 3000 invoices". Forged or expired state is refused.
Stateless
Built on MRTR from the 2026-07-28 revision. No pending table, no sticky sessions — it works behind a load balancer as it is.
Every client, every revision
Clients without elicitation are told to re-call with confirm: true. Same protection, one fewer round trip. Thresholds are yours, and the whole thing switches off.
★ SELF-SERVICE KEYS

Connect a team without becoming a key vending machine.

Issuing keys by hand stops working at about six colleagues. What happens next is predictable: somebody makes one shared key with every permission, which is exactly what scoping exists to prevent. Switch on self-service and each user issues their own — but the models, the permissions, the quota and the key limit all come from a template you set once. A user cannot widen their own key.

★ ONE-CLICK CONNECTOR

Connect Claude by pasting one link.

Every key has a Connect to Claude tab with a ready-to-paste URL, the key already embedded. Drop it into the Add custom connector dialog and you are live. A claude_desktop_config.json snippet and an mcp-remote command are on the same tab for the clients that want those instead.

★ SCOPED API KEYS

Issue. Limit. Audit. Revoke.

Every key runs as a specific Odoo user, so access rules apply as they always did. Pick the exact models, toggle read / write / create / delete, set a daily quota, a per-minute rate limit, an expiry, an IP allowlist. Tokens are stored as a SHA-256 hash — the clear value is shown once and then it is gone.

★ AUDIT LOG

Every call, on the record.

Method, tool name, target model, latency, source IP, outcome, and a SHA-256 of the arguments for non-repudiation. Retention is configurable and a cron trims it. Security webhooks fire to Slack on failed auth, out-of-scope attempts and quota breaches.

★ CUSTOM TOOLS

Teach it your business, without code.

The built-in tools are primitives, so the model has to work out what "overdue" means in your Odoo. Define a tool in the interface instead: a model, a domain with typed parameters, the fields you want back. Parameters are substituted as Python literals, so a value can never inject its own clause. Broken domains are caught when you save, not at 3am inside an answer.

★ PROTOCOL

Current, and still kind to old clients.

MCP has been revised five times, and 2026-07-28 is a breaking redesign: no handshake, no protocol-level sessions, every request self-contained. A server that speaks one revision is broken for somebody. This one negotiates per request.

Five revisions, negotiated per call
2026-07-28, 2025-11-25, 2025-06-18, 2025-03-26, 2024-11-05. A 2024-era client keeps working untouched after you upgrade; it never sees the new fields.
Structured output
Tools declare an outputSchema and return structuredContent, so a client stops parsing prose out of a text block and starts chaining calls reliably.
Streamable HTTP
A client that sends Accept: text/event-stream gets an SSE-framed response instead of falling back to a second, plainer request.
Resource templates
odoo://record/{model}/{id}, odoo://search/{model}?domain=..., odoo://metric/{name}, odoo://report/{name}/{id}, odoo://attachment/{id} — and a glossary resource.
Cursor pagination
Every list method pages with an opaque cursor, as the spec requires. Nobody gets to do arithmetic on it.
Safety annotations
Every tool carries readOnlyHint, destructiveHint and idempotentHint, so a client knows what may run unattended and what needs a person.
★ OAUTH 2.1

Connect a whole team without pasting tokens.

Pasting a bearer token into a connector URL puts it in browser history, proxy logs and screenshots. With OAuth a user clicks Connect, logs in to Odoo, sees a consent screen, and every call afterwards runs as them. Odoo is both authorization server and resource server, so there is no second system to install.

Discovery is automatic
RFC 9728 protected-resource metadata and RFC 8414 authorization-server metadata. The 401 tells the client where to go.
PKCE, S256 only
Plain is not offered. Client ID Metadata Documents are the registration path, with Dynamic Client Registration accepted for clients that only speak that.
Audience-bound tokens
RFC 8707. A token minted for another MCP server is refused here — the confused-deputy attack the spec names. Refresh rotation, and a replayed code revokes every token it issued.

Settings, a prompt library the assistant can list and fetch, and security webhooks that fire on failed auth, refused scope and quota breaches.

FIVE-MINUTE QUICKSTART

Connected before your coffee goes cold.

1. Install mn_mcp_server.
2. MCP Server → API Keys → New. Pick the Odoo user, choose the models, tick the permissions.
3. Open the Connect to Claude tab and copy the URL. Your key is already in it.
4. In Claude → Settings → Connectors → Add custom connector → paste → Add. Your Odoo must be reachable over https.
5. Open the Playground and run one call, so you find a missing permission now rather than in somebody else’s chat window.
6. Ask: “Which customers are overdue, and by how much?”

Then write down three things in the Semantic Layer — what "overdue" means, which model revenue comes from, and one metric. That is the difference between an assistant that is impressive and one that is trusted.
